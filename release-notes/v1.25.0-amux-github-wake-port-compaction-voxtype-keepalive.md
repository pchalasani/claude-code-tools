# v1.25.0 — `amux`, GitHub reply wakeups, compaction-aware porting, voxtype keepalive

## New: `amux` — find the agent that's waiting on you (PR #164)

`amux` finds and jumps between the Claude Code and Codex CLI agents
running across your tmux panes. An agent blocked on a question is
otherwise invisible among a hundred panes; that is the problem this
solves.

```
amux              # fzf picker, sorted by urgency, live pane preview
amux list         # table of every live agent (--json for scripts)
amux scan         # refresh the cache
```

States, most urgent first: **input** (stopped, asking you something),
**busy** (mid-turn), **bg** (monitors running), **idle**. Each row
carries the session name, model, and `repo@branch`.

Identification comes from child-process argv, because
`pane_current_command` cannot tell these harnesses apart — Claude Code
reports a bare version string and Codex reports `node`. State comes
from the screen. Codex has no structured prompt UI, so its
"waiting for input" detection is a heuristic and may need tuning.

Docs: [amux](https://pchalasani.github.io/claude-code-tools/tools/amux/)

## New: `github-wake` — resume when a GitHub reply lands (PR #165)

A session blocked on a collaborator's answer can now sleep until the
reply arrives instead of polling or being abandoned.

```
github-wake ISSUE_URL                    # from a Codex session
github-wake --claude-monitor ISSUE_URL   # from Claude Code (via Monitor)
```

A durable shared watcher records the request and wakes the originating
conversation on the first future comment. Polling and storage are
agent-neutral, with separate Codex and Claude adapters; Claude Code
2.1.98+ is delivered through its native Monitor tool.

The same PR hardens `codex-dynamic`: orphaned app-servers no longer
retain transcript writer locks, plugin fingerprinting ignores volatile
cache metadata that could fail startup checks, and resume behavior is
more reliable.

Docs: [github-wake](https://pchalasani.github.io/claude-code-tools/tools/github-wake/)
·
[codex-dynamic](https://pchalasani.github.io/claude-code-tools/tools/codex-dynamic/)

## Fix: `aichat port` respects compaction boundaries (PR #160)

Porting flattened the **entire** append-only session log in both
directions, including history the source agent no longer sends to the
model after compaction. A real 108-compaction codex rollout (191 MB)
ported into a ~6M-token Claude transcript that could never be
resumed — instant *context window full*, despite Claude's 1M window.

Both porters now mirror the source agent's own resume semantics:

- **codex → claude**: the last usable `compacted` record is a
  history-replacement point. Everything before it is dropped and the
  transcript starts from its `replacement_history`, followed by the
  post-compaction records. Legacy plaintext summaries are kept as a
  user message.
- **claude → codex**: the porter starts from the last main-chain
  `isCompactSummary` user line, whose plaintext already summarizes the
  dropped history.

Also removed: codex re-injects the active goal as a
`<codex_internal_context source="goal">` user message every turn,
which accounted for 16% of a ported transcript.

Docs: [aichat port](https://pchalasani.github.io/claude-code-tools/tools/aichat/port/)

## Fix: voxtype `keepalive_minutes` — no slow takes after idle (PR #168)

On a Mac under memory pressure, macOS evicts the idle Parakeet-MLX
model (~1.7 GB) to swap, and the first take after a pause pays a
multi-second page-in stall — observed: 8.4 s of audio decoded in
6.16 s, against ~0.2 s warm.

New opt-in config key (parakeet-mlx only):

```toml
keepalive_minutes = 5.0   # 0 disables (default); max 1440
```

After that many minutes without a decode, voxtype decodes half a
second of silence, keeping the model's pages in active use. It skips
itself during a take, during an utterance, while a hotkey command is
queued, and for 30 s after any activation, so it stays out of the way
of real speech. Known limitation, documented in full: the keepalive
briefly pauses capture, so a hotkey press landing exactly as it starts
can clip the first moment of dictation (issue #169 tracks decoupling
capture from decoding).
